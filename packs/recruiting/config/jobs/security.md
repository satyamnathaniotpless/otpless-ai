## Outreach hook patterns

- Reference a specific finding, CVE, or bug-bounty result: "saw your {finding/CVE} — the attacker-economics depth this role is built around."
- For fintech/identity-under-regulation backgrounds: lead with RBI/DPDP-scrutiny experience.
- For CTF/community-active candidates: mention their team/ranking as the hook.

## Candidate bar

**Hard requirements**
- Real appsec depth: web, mobile, and API pentesting.
- Reads and writes code well enough to ship the fix themselves.

**Strong signals**
- Has worked on identity, auth, or fraud; understands attacker economics — OTP interception, SIM swaps, session hijacking, bot farms.
- Communicates risk in a way engineers act on.
- Built own product / OSS contributor / identity-auth depth (universal preference, all roles).

**Auto-advance signals**
- Strong Q1 artifact — a real finding, CVE, published research, or security tool.
- Strong Q4 identity/auth/fraud depth answer.

**Auto-reject signals**
- No security artifact, only certifications with no hands-on finding/fix history.
- Generic AI-written answers with no specifics about a real vulnerability or attack class.

## Work-sample brief

Threat-model the public SDK/API surface described in OTPLESS's own docs: identify the top attack paths across the mobile SDKs, public APIs, and internal systems, and propose the highest-leverage fix for each. 2–3 hours. AI tools required.
